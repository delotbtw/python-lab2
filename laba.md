# Часть 1. Задание

## Результат

Пакет `streamstats`, читающий события из CSV и JSONL и создающий статистический отчёт.

## Модель события

Обязательные поля:

```
timestamp: ISO 8601
level: DEBUG | INFO | WARNING | ERROR | CRITICAL
source: непустая строка
message: строка
```

## CLI

```
python -m streamstats analyze INPUT [INPUT ...] --format csv|jsonl --output REPORT.json
python -m streamstats analyze INPUT --format jsonl --skip-invalid
```

## Обязательная функциональность

- Читать входные файлы построчно.
- Не использовать `read()` без ограничения и `readlines()` для всего файла.
- Поддержать CSV с заголовком и JSONL.
- Валидировать обязательные поля.
- Посчитать общее число событий.
- Посчитать количество событий каждого уровня.
- Посчитать количество событий каждого источника.
- Вывести top-5 источников ошибок уровня ERROR/CRITICAL.
- Найти первую и последнюю временную метку.
- Сформировать JSON-отчёт.
- Объединять статистику нескольких файлов.

## Ошибочные строки

- **Режим по умолчанию:** остановить обработку, вывести номер файла и строки, завершить CLI с кодом `2`.
- **Режим `--skip-invalid`:** пропустить строку, записать WARNING в лог, добавить число пропущенных строк в отчёт.

## Исключения

Создать базовое `StreamStatsError` и отдельные ошибки:

- неподдерживаемый формат;
- неверное событие;
- неверная временная метка;
- ошибка конфигурации CLI.

Не перехватывать `Exception` без повторного возбуждения или преобразования в понятную ошибку на границе CLI.

## Обязательные проверки

- Пустой файл создаёт нулевой отчёт без падения.
- Один файл CSV и эквивалентный JSONL дают одинаковую статистику.
- Несколько файлов агрегируются без потери событий.
- Кириллица сохраняется в сообщениях и отчёте.
- Неверный JSON в строке 7 сообщает строку 7.
- Неверная дата сообщает поле и строку.
- Без `--skip-invalid` обработка прекращается.
- С `--skip-invalid` остальные строки учитываются.
- Top-5 сортируется детерминированно при равных значениях.
- Исходные файлы не изменяются.
- Большой вход не читается целиком.

## Проверка потоковости

Полный балл за потоковость ставится при выполнении всех условий:

- parser возвращает iterator/generator или обрабатывает запись по одной;
- отсутствует `readlines()` и полный `list(file)`;
- агрегация не хранит все события;
- студент объясняет объём дополнительной памяти.

Если все события накапливаются в списке, за критерий ставится не более 5 из 15.

## Начисление за тесты — 15

- 4: parser CSV/JSONL;
- 3: граничные и повреждённые строки;
- 3: несколько файлов и агрегация;
- 3: CLI и временный каталог;
- 2: тесты независимы и детерминированы.

## Защита

1. Добавить уровень `NOTICE` либо объяснить, где должна находиться его валидация.
2. Изменить top-5 на top-N без копирования логики.
3. Показать место, гарантирующее построчную обработку.
